# Agent Note: 会话模型选择器中新增自由文本筛选

状态: 已实现

[English](2026-08-30-composer-model-filter.md) | 中文

## 问题

会话模型选择位（`conversation.input.model`）把每个提供方的模型都渲染在同一个滚动列表里。自定义提供方变多后列表会变长，而两级菜单会先把用户带进某个提供方分组，才能进一步缩小范围。按名称挑一个已知模型（最常见的情况）不该要求逐行扫视或滚过无关的提供方。

## 决策

在模型面板（下钻后的列表）顶部、提供方分组之上新增一个自由文本筛选行。它按模型显示名、模型 id、以及提供方名称做不区分大小写的匹配，并丢弃没有任何命中的提供方分组。查询为空时保留完整目录；非空查询但无命中时显示专门的 `empty.filter` 提示，而不是 `empty.models`（目录为空）提示。

筛选是面板局部状态：菜单关闭、Esc 从模型面板退回根面板、以及从根面板下钻进入模型面板时都会重置。筛选框带 `autoFocus`，键盘用户下钻后即落入其中；既有的 `ArrowUp`/`ArrowDown` 漫游处理器会把焦点移入筛选后的模型行。清空（`×`）按钮仅在查询非空时出现。

筛选纯属展示层：它不触碰共享的 `ModelDirectory` 状态或 Host 的选择路径，所以被过滤掉的当前模型仍保持选中，触发器标签也不受影响。即使目录缺少友好名称，提供方本地的模型 id 仍会命中，因为 id 也参与匹配。

语言键 `filter.placeholder`、`filter.aria`、`filter.clear`、`empty.filter` 加入 `model` 命名空间字典（`zh` 为真值来源，`en` 与其完整对齐）。

## 考虑的替代方案

**在根面板做筛选。** 根面板只显示「模型/推理等级」两个单元格而非列表，根面板筛选必须先切面板才有意义。把筛选框放在模型面板，使其紧挨被缩小的行。

**提供方下拉 + 文本搜索双控件。** 两个控件把一个意图（找模型）的决策面翻倍。一个覆盖分组行的文本字段，通过名称/id 匹配同时覆盖「按提供方」和「按模型」两类查询。

## 影响

模型面板新增一个始终可见的输入框及其键盘入口（`autoFocus`）。由于筛选纯属展示层且为面板局部状态，它不新增任何会话状态、不触发任何 Host 往返、也不改变选择契约；共享目录与选择动词均未改动。`model` 语言命名空间新增四个键，并在 `en` 中保持完整。`tests/model-select.client.spec.tsx` 的三个筛选场景使组件覆盖率维持在 100%。
